# درگاه بک‌اند ابرهمراهی

این پروژه یک درگاه مستقل FastAPI برای استفادهٔ سایت‌ها از فضای ابری ابرهمراهی است. مسیرهای ورود و فایل از APK نسخهٔ `1.5.14.00` استخراج شده‌اند و ورود با رمز، فهرست فایل‌ها و پوشه‌ها در آزمایش اولیهٔ کاربر با موفقیت پاسخ داده است.

امکانات فعلی:

- اتصال هر سایت با توکن اختصاصی محدود به دامنه و امضای HMAC برای درخواست‌های بک‌اند؛
- دریافت captcha، ارسال پیامک، ورود با کد تأیید و تعیین رمز؛
- ورودهای بعدی با رمز و تمدید خودکار توکن ابرهمراهی؛
- ذخیرهٔ کاربران، نشست‌ها، توکن‌های رمزگذاری‌شده و فایل‌ها در SQLite؛
- فهرست فایل و پوشه، ساخت پوشه، دریافت لینک دانلود و بارگذاری چندبخشی؛
- ساخت خودکار لینک دائمی `cdn` برای فایل‌های موجود و فایل‌های بارگذاری‌شده؛
- نمایش سهمیه، فضای مصرف‌شده و باقی‌مانده و حذف بازیابی‌پذیر یا دائمی فایل؛
- کنسول مدیریتی چندحسابه در مسیر `/testpage` با داشبورد ظرفیت، درخت فایل،
  بارگذاری، دانلود و حذف؛
- صفحهٔ حساب‌ها با نام نمایشی، شماره، وضعیت اتصال، ویرایش، وریفای مجدد،
  حذف نشست و حذف رکورد محلی؛
- صفحهٔ تنظیمات توکن دامنه، سایدبار جمع‌شونده و حرکت‌های رابط با GSAP؛
- صفحهٔ واحد ایجاد و لغو توکن دامنه؛
- مستندات تعاملی OpenAPI؛
- نصب خودکار systemd و Nginx روی `https://srun.ir/abrehamrahi`.

## امنیت داده‌ها

رمز کاربر هرگز به شکل قابل‌بازیابی ذخیره نمی‌شود و با Argon2 هش می‌شود. توکن‌های ابرهمراهی و کلیدهای امضا با Fernet رمزگذاری می‌شوند. شناسهٔ نشست و توکن سایت نیز فقط به‌صورت SHA-256 در پایگاه‌داده قرار می‌گیرند. فایل `.env`، SQLite و کلیدها در Git ثبت نمی‌شوند.

## اجرای محلی

```bash
python -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
cp .env.example .env
```

مقادیر `ENCRYPTION_KEY` و `ADMIN_PASSWORD` را در `.env` تنظیم و متغیرها را بارگذاری کنید:

```bash
set -a
source .env
set +a
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8765 --reload
```

مسیرهای مهم محلی:

- مستندات: `http://127.0.0.1:8765/docs`
- صفحهٔ توکن: `http://127.0.0.1:8765/admin/tokens`
- برگهٔ آزمایش: `http://127.0.0.1:8765/testpage`
- سلامت سرویس: `http://127.0.0.1:8765/health`

## گردش پیشنهادی مشتری

1. مدیر در `/admin/tokens` برای دامنهٔ سایت، `client_token` و `signing_secret` می‌سازد.
2. بک‌اند سایت با `POST /v1/auth/sms/request` پیامک می‌فرستد.
3. با `POST /v1/auth/sms/verify` کد و در صورت تمایل `new_password` را ارسال می‌کند. پاسخ شامل نشست کاربر است.
4. در دفعات بعد `POST /v1/auth/login` با شماره و رمز استفاده می‌شود.
5. نشست کاربر در `Authorization: Bearer ...` و توکن سایت در `X-ABR-Client-Token` ارسال می‌شوند.
6. بارگذاری از `POST /v1/files/upload` یک `cdn_url` ثابت و یک `download_url` موقت برمی‌گرداند.

لینک `cdn_url` را در دیتابیس سایت ذخیره کنید. این لینک هنگام مراجعه، لینک امضاشدهٔ تازه می‌گیرد و به فایل هدایت می‌کند. این سامانه در نقش «درگاه فایل با URL پایدار» است؛ شبکهٔ توزیع جغرافیایی واقعی به تنظیم CDN جداگانه‌ای مانند Cloudflare نیاز دارد.

اگر ورود پیامکی در ابرهمراهی موفق شود ولی endpoint تغییر رمز از طرف ابرهمراهی
پذیرفته نشود، نشست موفق از بین نمی‌رود. پاسخ `sms/verify` در این حالت
`password_warning` و `upstream_password_configured=false` دارد و کنسول هشدار را
کنار همان حساب نشان می‌دهد. رمز خام در هیچ مرحله‌ای ذخیره نمی‌شود.

## استقرار

دستور کامل نصب روی سرور:

```bash
ssh -p 2233 root@5.61.27.185
git clone https://github.com/ostaddehdari/abrehamrahi.git /opt/abrehamrahi
bash /opt/abrehamrahi/deploy/install.sh
```

راهنمای دقیق، به‌روزرسانی و عیب‌یابی در [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) آمده است. فهرست APIهای بازیابی‌شده از APK در [docs/UPSTREAM_API_CATALOG.md](docs/UPSTREAM_API_CATALOG.md) و APIهای همین درگاه در Swagger قرار دارند.

## محدودیت شواهد

این مخزن ادعای دسترسی به مستندات داخلی سرور ابرهمراهی ندارد. کاتالوگ upstream فهرست مسیرهایی است که در APK مشاهده شده‌اند. روش و مدل مسیرهای اصلی ورود، فهرست، دانلود و بارگذاری با شواهد قوی‌تری بازیابی شده‌اند؛ سایر مسیرها تا زمان آزمایش زنده با برچسب اطمینان مشخص شده‌اند.
